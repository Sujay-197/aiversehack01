aiversehack01

Problem:
Students fail to convert skills into opportunities due to scattered resources, weak guidance, and no learning loop from rejections.

Solution:
An Agentic AI system that continuously:

Understands user profile

Reasons over market demand

Plans learning + application strategies

Executes actions via workflows

Learns from rejections and adapts

Core Differentiator:
👉 Rejection-driven replanning using a closed feedback loop.

SYSTEM ARCHITECTURE

Design Principle:

n8n = execution spine, not the brain.

Layers

Reasoning Layer

LLM-based Planner & Reflection logic

Generates plans, decisions, strategy shifts

Execution Layer

n8n workflows (hosted locally)

Scheduling, integrations, approvals, actions

Memory Layer

PostgreSQL → structured truth

Vector DB (Qdrant/Pinecone) → semantic memory (if needed)

UI Layer

Next.js dashboard

Action cards + career timeline

AGENTS (WHAT EXISTS AND WHERE)

1. Profile Intelligence Agent

Extracts skills from resume, GitHub

Maintains confidence-weighted skill profile
Runs via: n8n + LLM

2. Market Reasoning Agent

Tracks job/internship/hackathon trends

Maps skills ↔ demand
Runs via: n8n (batch) + embeddings

3. Planner Agent (Core Brain)

Converts goals → weekly strategies

Replans after failure
Runs via: LLM + custom logic (outside n8n)

4. Action Agent

Applies, drafts resumes, schedules tasks
Runs via: n8n (human-in-the-loop)

5. Reflection & Feedback Agent

Analyzes rejections

Classifies failure cause

Feeds insights back to Planner
Runs via: n8n + LLM
This is the innovation hook

🔹 TECH STACK (MINIMAL, HIGH-SIGNAL)

LLM: Gemini CLI or smth similar with a free plan

Agent Logic: Custom or LangGraph-lite

Workflow Engine: n8n

Backend: FastAPI

Frontend: Next.js + Tailwind

DB: PostgreSQL

PHASE 0 — AI CONTRACT (NON-NEGOTIABLE)

Prompt:

You are designing the thinking brain of an AI system.

Define the minimum conditions under which this system can honestly be called “AI” and not automation.

Output:

What internal state must persist across time

What must change after failure for learning to be real

What evidence would convince a skeptic that intelligence exists

Reject any requirement that is execution- or workflow-related.

PHASE 1 — INTELLIGENCE STATE (NOT DATA MODELING)
1️⃣ Strategy as a First-Class Object

Prompt:

Treat “strategy” as a living, evolving object.

Define:

What a Strategy Version contains

Which parts are hypotheses vs decisions

What makes two strategies meaningfully different

Constraint:
Strategy must be comparable across time (t → t+1).

Output a structured definition, not implementation details.

2️⃣ Failure → Insight Mapping (LEARNING CORE)

Prompt:

You are designing the learning loop of an AI system.

Define how raw failure signals (rejections, ghosting) become generalizable insights.

For each step, explain:

What is inferred

What uncertainty remains

How confidence is updated

This mapping must enable future decisions to change, not just generate advice.

PHASE 2 — PLANNER AGENT (THE BRAIN)
1️⃣ Strategy Generation (Reasoning Required)

Prompt:

You are the Planner Agent.

Input:

Current Strategy Version

Historical Strategies

Accumulated Failure Insights

User constraints and goals

Task:
Generate Strategy Version N+1 such that:

It differs only where justified by evidence

Every change is explicitly defended

Uncertainty is acknowledged, not hidden

Output:

Strategy N+1

Strategy Diff (Added / Removed / Deprioritized)

Reasoning trace for each change

If no change is warranted, state why.

2️⃣ Hypothesis Testing (Anti-Randomness)

Prompt:

You are an AI that learns by testing hypotheses.

Given:

A strategy decision

Subsequent outcomes

Decide whether the hypothesis was:

Supported

Weakly contradicted

Strongly contradicted

Update confidence accordingly and explain how this affects the next strategy.

Do not recommend actions. Focus only on belief updates.

PHASE 3 — REFLECTION AGENT (INTELLIGENCE AMPLIFIER)

Prompt:

You are the Reflection Agent.

Input:

Rejection or non-response

Strategy decision that led to it

Task:

Determine whether the failure challenges:

Skill assumptions

Market assumptions

Positioning assumptions

Extract one strategy-level insight, not advice

Estimate confidence of this insight

Output must be usable by a Planner to change beliefs, not actions.

PHASE 4 — MEMORY AS BELIEF, NOT STORAGE

Prompt:

You are designing memory for an AI that reasons over time.

Categorize system memory into:

Beliefs (with confidence)

Evidence

Decisions

Outcomes

Define:

What must never be overwritten

What must decay or be revised

How conflicting beliefs are handled

Avoid mentioning databases or tools.

PHASE 5 — EXECUTION IS SECONDARY (BOUNDARY SETTING)

Prompt:

Define a strict boundary between:

Intelligence (thinking, deciding, learning)

Execution (doing)

For each, list:

Responsibilities

Things it is explicitly forbidden from doing

The goal is to ensure execution cannot fake intelligence.

PHASE 6 — AI PROOF MOMENT (JUDGE-KILLER)

Prompt:

Design a single demo moment that proves real learning occurred.

The demo must show:

An initial belief

A failure that contradicts it

A revised belief

A visibly different strategy

Describe this as a cause → effect → adaptation sequence.

If the demo can be replicated with rules, reject it and redesign.
