# Aiversehack01 Implementation Plan & Chain of Thought

## Goal Description
Build an Agentic AI system that functions as a **Belief Testing Engine** for career development. Instead of simply "recommending" jobs, it creates a **"Failure Passport"**—a set of assumptions about the user's fit for the market—and generates **experiments** (applications, projects) to test and refine those assumptions. The goal is to move from "Unknown" to "Confident" through a closed feedback loop of failure and reflection.

## Chain of Thought: Philosophical Shift
*   **Old View:** User has skills -> AI finds matching jobs -> AI applies -> Success/Fail.
*   **New View (The "Scientist"):** 
    *   **State:** A set of *Beliefs* (e.g., "User is fit for Backend at Series A startups") with *Confidence Scores*.
    *   **Action:** An *Experiment* designed to test a specific Belief (e.g., "Apply to 5 Series A startups to test market response").
    *   **Outcome:** Failure is not just "bad news", it's *Data* that updates the Belief State.


### Option 1: The "Low-Code Orchestrator" (n8n Heavy)
*   **Concept:** Use n8n for almost everything. Logic is embedded in n8n "Code" nodes or "AI Agent" nodes.
*   **Pros:** Rapid prototyping, visual debugging of flows, easy integrations (Gmail, Sheets, etc.).
*   **Cons:** Complex reasoning (the "Brain") becomes hard to manage in a flowchart. "State" (Strategy versions) is difficult to version control and diff within n8n.
*   **Verdict:** Good for the "Hands" (Execution), bad for the "Brain".

### Option 2: The "Code-First Monolith" (LangGraph/LangChain)
*   **Concept:** A Python application using LangGraph to manage state and agent transitions.
*   **Pros:** Ultimate control over the "Brain", memory, and state transitions. Best for implementing the "Strategy Diff" and "Reflection" logic.
*   **Cons:** Re-implementing integrations (Gmail API, LinkedIn scraping) is tedious and brittle compared to n8n.
*   **Verdict:** Good for the "Brain", tedious for the "Hands".

### Option 3: The "Hybrid Cortex" (Recommended)
*   **Concept:** 
    *   **Brain (Python/FastAPI):** Handles state, strategy generation, reflection, and decision making. Exposes API endpoints like `/generate-plan`, `/reflect-on-failure`.
    *   **Hands (n8n):** Handles dirty work. Polls emails, scrapes sites, submits forms. Calls the Brain API to get instructions or report results.
    *   **Memory (PostgreSQL):** Shared source of truth.
*   **Why:** Leverages n8n's strength in connectivity and Python's strength in complex logic/data structures. Aligns perfectly with the provided `initplan.txt` architecture.

## Ground 0 to MVP Roadmap

### Phase 0: The Foundation (Infrastructure)
*   **Objective:** Set up the environment where the Brain and Hands will live.
*   **Tech:** GitHub, PostgreSQL, n8n.
*   **Steps:**
    1.  **Repo Setup:** Monorepo structure.
    2.  **Database:** Schemas for `User`, `Evidence` (Raw Data), `BeliefState` (The Passport), `Experiment` (Actions), `Outcome`.
    3.  **n8n:** Connect to DB.

### Phase 1: Identity Capture & The Failure Passport (The Brain v1)
*   **Objective:** Build the "Passport v0" creation logic. **NO RATING, ONLY CAPTURING.**
*   **Tech:** Python, FastAPI, Pydantic.
*   **Steps:**
    1.  **Evidence Collection:** Endpoint to take Resume/GitHub -> Store as "Claimed Skills" & "Demonstrated Skills".
    2.  **Passport Generation:** Logic to synthesize Evidence into *Assumptions* (e.g., "Assumption: User knows Python"). Assign initial *Confidence Scores*.
    3.  **Gap Analysis:** Identify "Known Unknowns" (e.g., "We don't know if the user can pass a LeetCode medium").

### Phase 2: Hypothesis Engine (Reasoning Core)
*   **Objective:** The engine that says "Here is how we test your assumptions."
*   **Modes:**
    *   **Mode A (Hypothesis-Guided):** "Confidence in 'Frontend Skills' is low. Suggestion: Build a React App to increase confidence."
    *   **Mode B (User-Driven):** User: "I want a Google job." System: "Okay, existing belief state says you are 40% confident for Big Tech. Here is the gap."
*   **Steps:**
    1.  **planner_agent:** Takes `Passport` -> Generates `Experiments` (Batch of actions).
    2.  **Opportunity Surfacer:** **NOT a recommender.** Finds hackathons/jobs that *best test the current hypothesis*.

### Phase 3: The Hands (Execution & Experiments)
*   **Objective:** Run the experiments.
*   **Tech:** n8n.
*   **Steps:**
    1.  **Experiment Runner:** Submit applications, track submissions.
    2.  **Outcome Monitor:** Watch for "Rejection", "Ghosting", "Invite".
    3.  **Feedback Loop:** Feed outcomes back to the Belief Engine to update Confidence Scores.

### Phase 4: The Face (UI as a Lab Notebook)
*   **Objective:** Visualize the "Science" of the career.
*   **Tech:** Next.js.
*   **Steps:**
    1.  **Passport View:** Visualization of the User's Belief State (Skills + Confidence bars).
    2.  **Experiment Dashboard:** Active tests, incoming results.
    3.  **Insight Log:** "We learned that you are not getting passing checks on Resume Screenings (Confidence in 'Resume Quality' dropped)."

## MVP Success Criteria (The "AI Proof Moment")
1.  **Onboarding:** User uploads Resume. System builds **Passport v0** (e.g., "Belief: Good at Python", Confidence: 0.5).
2.  **Hypothesis:** System suggests: "Apply to 5 Python Internships to test this belief."
3.  **Experiment:** User approves. n8n applies.
4.  **Outcome:** 5 Rejections.
5.  **Learning:** System updates Passport: "Belief: Good at Python" -> Confidence: 0.2. "New Assumption: Resume keyword mismatch".
6.  **Next Step:** System proposes **Mode A**: "Rewrite Resume with these keywords" (to increase confidence).
